# 메타데이터 관리 앱
## 1. 프로젝트 개요
### 1.1 프로젝트명
메타데이터 관리 앱
### 1.2 프로젝트 목적
데이터 표준을 관리하기 위한 메타 데이터를 관리
### 1.3 개발 범위
- 표준 단어 관리 기능
- 표준 용어 관리 기능
- 표준 도메인 관리 기능

## 2. 기술 스택
- 프런트엔트 : HTML, CSS, 리엑트, 자바스크립트
- 백엔트 : Node.js, Express
- 데이터베이스 : PostgreSQL

## 3. 기본 사항
- 프런트엔드와 백엔드를 따로 개발
- 기본적인 웹 기술만 사용

## 4. 상세 기능 설명
### 4.1 표준 단어 관리
#### 4.1.1 표준 단어 구성 요소
- 단어명
•	일정한 뜻을 갖는 최소 단위의 단어로 한글로 작성하는 것을 원칙으로 한다.
•	한글 맞춤법과 표준어 규정을 준수하며 10자 이내로 작성할 것을 권장한다.
- 영문명
•	단어가 가지는 의미에 대한 영문단어 또는 영문 Fullname이다.
•	단어명이 약어인 경우, 원어에 대한 영문단어로 정의한다.
- 영문약어
•	물리 데이터 모델 및 물리 데이터베이스 객체 명칭을 정의하기 위해서 용어의 한글명(논리명)을 물리명으로 변환하는데 사용된다.
•	영문약어는 영문명을 바탕으로 정의하며 대문자로 명기한다.
- 설명	
•	사용자가 데이터의 의미를 가장 잘 이해할 수 있도록 언어로 표현한다.
•	업무 관점에서 범위와 자격 요건을 명시함으로써, 데이터 명칭만으로는 사용자에게 전달하기 어려운 사항들을 전달할 수 있다.
•	데이터 사용자가 데이터의 의미를 잘 이해할 수 있도록 관련 업무를 모르는 사용자 입장에서 기술한다.
•	서술식 정의만으로 의미 전달이 어려운 경우 발생 데이터 값의 예시나 공식 등을 기술한다.
•	데이터 명칭을 그대로 서술하거나 약어 또는 전문 용어를 이용한 기술은 가급적 지양한다.
- 단어구분	
•	단어 구분은 수식어, 주제어, 분류어로 나뉜다.
•	수식어 : 뒤에 오는 말을 수식하거나 한정하기 위하여 사용하는 단어
•	주제어 : 용어의 중심이 되는 단어
•	분류어 : 용어의 의미와 데이터 형식 및 길이를 한정할 수 있는 단어로서 도메인의 근간이 되며, 엔터티명에서 사용하는 분류어와 속성명에서 사용하는 분류어로 나누어진다.
– 엔터티 분류어 : 엔터티 유형과 의미를 명확하게 하기 위해 엔터티명 뒤에 붙이는 단어
(예) 공통, 상세, 이력, 목록, 내역 등
– 속성 분류어 : 속성 값의 유형을 명확하게 하기 위해 속성명 뒤에 붙이는 단어
(예) 코드, 번호, 명, 내용, 금액, 일자 등
•	표준단어사전에서는 엔터티 분류어 여부와 속성 분류어 여부만을 관리한다.

#### 4.1.2 단어 정의 기본 지침
- 사용자들이 단어의 의미를 명확하게 파악할 수 있도록 정의한다.
- 단일어 형태의 단어를 표준단어로 정의하는 것을 기본으로 한다.
(예) 고객, 가격, 금액, 결제
- 명사형으로 정의하며 동사, 부사, 접속사, 조사, 복수 표시 또는 소유격 형태의 단어는 사용하지 않는다.
(예) 예상되는금액 -> 예상+금액(O) / 되는(X)
    가장최근에접속한일자 -> 최근+접속+일자(O) / 가장(X), 에(X), 한(X)
- 공백을 포함하여 특수문자는 사용하지 않는다. 특수문자는 유사발음의 문자로 대체하여 정의한다. 단, 시스템명 또는 고유명사에 포함되어 있는 특수문자를 제거하면 단어 식별이 어렵거나 의미 전달에 왜곡이 발생하는 경우에는 예외적으로 허용한다..
(예) E-MAIL(X)->EMAIL(O), BSS-OSS(O), ICIS-NS(O)
- 동일한 의미의 단어를 한글과 영문으로 중복해서 정의하지 않는다.
(예) 금액(O), AMOUNT(X)
- 시스템에서 사용하는 단어를 표준화 할 경우, 먼저 한글로 표준화를 검토하고 한글로 전환이 어려운 경우에는 외래어 사용을 검토한다.
(예) 한글로 표준화 하는 경우: Party -> 당사자, Agrement -> 계약
    외래어로 표준화 하는 경우: Table -> 테이블, Segment -> 세그먼트, Event -> 이벤트
- 업무 중요성과 사용 빈도수를 고려하여 표준단어를 정의한다.
- 축약된 단어는 의미가 모호하므로 되도록이면 사용하지 않고, 사용이 예상되는 축약어는 이음동의어로 관리한다.
(예) 기변(X) -> 기기변경(O), 명변(X) -> 명의변경
- 축약된 단어를 범용적으로 사용하는 경우에는 예외적으로 등록하여 사용할 수 있다. 
- 용어의 영문명이 지나치게 길어지는 것을 방지하기 위해 관용적으로 축약어를 사용한 경우에는 표준단어로 순화한 복합어를 표준단어로 정의하고 복합어를 단일어처럼 등록하여 사용한다.
(예) 번호+이동 -> 번호이동
- 경제 용어, 세무 용어, 법률 용어 등의 전문 용어이거나 낱개 단어로 분리하기 어렵고 분리 시 의미 전달이 모호해지는 경우에는 해당 용어를 표준단어로 등록한다.
(예) 네트워크론, 부가가치세
- 분류어는 개체의 유형을 명확하게 나타낼 수 있는 단어로 선정한다.
- 동일한 단어가 속성 분류어와 엔터티 분류어로 동시에 사용될 수 있으므로 속성 분류어 여부와 엔터티 분류어 여부를 구분하여 관리한다.
(예) 내역 : 속성분류어(X), 엔터티분류어(O),
    코드 : 속성분류어(O), 엔터티분류어(O)
- 영문명(Full Name)은 띄어쓰기를 허용하며, 해당 단어의 구성을 알 수 있게 정의한다.
(예) 중소기업: Small And Medium Sized Business

#### 4.1.3 동음이의어 사용 지침
- 동음이의어(한글단어명 기준)는 기본적으로 허용하지 않으나 대체 단어가 없는 경우에는 사용할 수 있다.
(예) 수입(輸入, Import), 수입(收入, Earning)
    전문(The Message of a Telegram), 전문(Professional)
    CRM(Customer Relationship Management), CRM(Credit Risk Management)
- 동음이의어를 사용하는 엔터티명, 속성명은 표준화 작업 수행 시에 자동 변환되지 않으며 사용자의 직접(수동)적인 선택이 필요하므로 사용을 최소화해야 한다.
- 동음이의어는 가급적 복합어로 구성하여 사용한다.
(예) 구(OLD)와 구(GU:지역)가 동음이의어로 존재시, 구(OLD) 삭제 후 복합어 등록
  -> 구멤버십, 구조직

#### 4.1.4 동음이의어 사용 지침
- 소리는 다르나 의미가 동일한 이음동의어는 대표 단어를 선정하여 표준단어로 정의하고, 나머지 이음동의어는 표준단어에 대한 동의어 그룹으로 정의하여 표준단어를 제시 받을 수 있도록 관리한다.
(예) 이동전화, 휴대전화, 핸드폰 => 이동전화(표준), 휴대전화/핸드폰(동의어)
    대출, 대부, 융자, 차금 -> 대출(표준), 대부/융자/차금(동의어)
- 표준단어가 존재하는 이음동의어는 추가로 표준단어로 정의하지 않으며, 필요 시 표준단어 변경을 검토한다. 단, 의미는 유사하더라도 어감에 따라 각각 다르게 사용되는 이음동의어는 표준단어로 정의한다. 단, 영문약어는 서로 다르게 정의해야 한다.
(예) 선택(Selection->SEL), 선발(Selection->SLETON), 발췌(Selection->SELCT)
    수정(Amendment->AMD), 정정(Correction->CORCT)
- 자주 사용되는 이음동의어는 반드시 동의어 그룹으로 관리한다.
- 이음동의어의 영문약어는 표준으로 정의된 대표 단어에 대해서만 정의한다.

#### 4.1.5 금칙어 사용 지침
- 금칙어는 이음동의어와 같이 표준단어에 대한 동의어 그룹으로 정의하여 표준단어를 제시 받을 수 있도록 관리한다.
- 오타 또는 문법상 오류가 존재하는 단어는 기존에 표준으로 사용하였어도 동의어 그룹으로 관리하지 않는다. 단, 자주 발생하는 맞춤법 오류 단어는 동의어로 관리하여 동일한 단어가 표준단어로 중복 등록되지 않도록 한다.
- 단어 처음에 오는 ‘ㄹ’과 단어의 처음에 ‘ㅣ,ㅑ,ㅕ,ㅛ,ㅠ’와 함께 사용되는 ‘ㄴ’은 두음법칙에 의하여 ‘ㄹ’은 ‘ㄴ’으로 ‘ㄴ’은 ‘ㅇ’으로 바꾸어 사용해야 하나 이러한 원칙에 맞지 않는 단어를 표준으로 채택한 경우에는 표준 맞춤법을 적용한 단어를 금칙어로 관리한다.
(예) 연도(금칙어) -> 년도(표준), 연간(금칙어) -> 년간(표준)
- 표준단어로 채택되지 않은 외래어는 금칙어로 정의한다.
(예) Process(금칙어) -> 프로세스(표준), Interface(금칙어) -> 인터페이스
- 경제용어, 전문용어, IT용어 중 관용적으로 영문의 두문자어(頭文字語,Acronyms)를 사용하는 경우에는 한글명를 금칙어로 정의한다.
(예) 데이터웨어하우스(Data-Warehouse: 금칙어) -> DW(표준),
    총계정원장(General Ledger: 금칙어) -> GL(표준)
- 축약된 형태의 단어(축약어)는 금칙어로 정의하여 사용을 방지한다.
(예) 주민번호(금칙어) -> 주민등록번호(표준), 사업자번호(금칙어) -> 사업자등록번호(표준)
- 사람에 해당하는 접미사 ‘자’와 ‘인’으로 구성된 파생어의 경우에는 접미사 사용 지침에 따라 ‘자’를 기본으로 적용하며 표준으로 채택되지 않은 나머지 단어는 금칙어로 관리한다.
(예) 신청인(금칙어) -> 신청자(표준)

#### 4.1.6 영문 및 외래어 사용 지침
- 단어명은 가급적 영문을 사용하지 않으며 한글로 정의하는 것을 원칙으로 하나 대체할 한글이 없거나 범용적으로 사용되는 영문 또는 고유한 업무적 의미를 담고 있는 경우에는 해당 영문 표기를 그대로 사용할 수 있다.
(예) B2C(Business To Customer), BSS(Business Support System)
- 국어처럼 사용하는 외래어는 영문으로 표기하지 않고 외래어 표기법에 따라 정의하는 것을 원칙으로 한다. 대응되는 영문단어는 동의어로 정의하여 사용을 제한한다.
(예) Email(동의어) -> 이메일(표준), PROCESS(동의어) -> 프로세스(표준)
- 한글 단어보다 더 친숙하게 사용하는 영문 단어의 경우에는 해당 영문 단어를 사용하고, 영문 단어에 대응하는 한글 단어 혹은 외래어는 동의어로 등록하여 관리한다.
(예) 인터넷프로토콜/아이피(동의어) -> IP(표준), 데이터웨어하우스(동의어) -> DW(표준)
- 영문을 한글화 할 경우 의미적으로 변환하는 것을 원칙으로 하나 발음대로 한글화 한 명칭이 더 관용적일 경우에는 이를 사용할 수 있다. 의미로 한글화 한 경우와 발음대로 한글화 한 경우 둘 다 자주 사용될 경우에는 의미로 한글화 한 단어를 표준으로 하고, 발음대로 한글화 한 단어는 동의어로 등록한다.
(예1) 의미로 한글화 한 단어를 표준으로 정의
    Password -> 비밀번호(표준), 패스워드(동의어)
    Error -> 오류(표준), 에러(동의어)
(예2) 발음대로 한글화 한 단어를 표준으로 정의
    Process -> 프로세스(표준)
- 영문을 의미로 한글화 한 경우와 발음대로 한글화 한 경우를 각각 어감에 따라 다른 의미로 사용하고자 하는 경우에는 제한적으로 표준단어로 사용할 수 있다. 단, 영문약어는 다르게 정의하여야 한다.
(예) ALARM(X) -> 경보(ALRM)(O), 알람(ALM)(O)
- 영문단어는 1Byte대문자로 정의하고, 가급적 특수문자는 사용하지 않는다. 단, 관용적으로 사용하는 단어나 고유명사인 경우 특수문자 중 ‘/’, ‘-‘, ‘&’ 만을 허용한다.
(예) Standard and Poor’s(S&P)
- 외래어는 사용을 지양하지만 외래어를 한글로 변환했을 때보다 외래어를 그대로 사용하는 이 더 친숙한 경우에는 외래어를 한글 단어로 사용한다.
(예) 서비스(O), 미디어(O)

#### 4.1.7 숫자 사용 지침
- 단어명 및 표준단어 구성요소에 포함되는 모든 숫자는 1Byte 아라비아 숫자를 사용한다.
- 숫자만으로는 단어가 될 수 없는 것을 원칙으로 하며, 해당 숫자의 의미를 한정하는 단어와 함께 복합어 형태로 정의해야 한다. 단, 서비스명과 같이 특정 의미를 갖는 숫자나 전사적으로 자주 사용하는 숫자는 예외적으로 등록하여 사용할 수 있다.
(예1) 복합어로 등록하는 경우
     080(X) -> 080서비스(O), 36(X) -> 36개월(O)
(예2) 숫자만으로 구성된 단어를 예외적으로 허용하는 경우
     1, 100, 1000, … : 단위나 범주를 표현하기 위해 자주 사용하는 숫자 단어
     365, 24 : 365일, 34시간 서비스 등을 표현하기 위해 자주 사용하는 숫자 단어
- 숫자와 조합된 단어의 의미가 불분명한 경우에는 단어로 정의하지 않고, 용어 정의시에 명확한 업무적 의미를 파악할 수 있도록 수식어를 추가한다.
(예) 일시1(X), 일시2(X) -> 사용권한1차승인일자, 사용권한2차승인일자
